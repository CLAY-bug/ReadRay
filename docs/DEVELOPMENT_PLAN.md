# ReadRay 开发计划

最后更新：2026-08-16

## 1. 项目定位

ReadRay 是一个 Windows 优先的本地英语学习 Agent。

它不是普通查词软件，也不是浏览器翻译插件，而是一个轻量的跨应用学习助手：

```text
在任意 App 中遇到英文理解障碍
-> 使用全局快捷键呼出
-> 捕获文本
-> 生成上下文解释卡
-> 保存为本地学习记忆
-> 生成个性化复盘任务
```

比赛叙事：

> ReadRay 将跨应用英文阅读中的即时障碍，转化为结构化、可本地保存、可复盘的学习事件。

中文定位：

> ReadRay 是面向跨应用英语阅读的本地个性化学习 Agent。

## 2. 核心原则

1. 优先面向 Windows 原生环境开发。
2. MVP 必须控制在单人可完成范围内。
3. 第一版不直接引入通用 Agent 框架运行时。
4. 参考成熟 Agent 的运行协议，在 Rust 中实现项目专属的轻量 Agent Runtime。
5. 不内置有版权风险的商业词典内容。
6. 第一版 LLM 供应商使用 DeepSeek。
7. 本地存储使用 SQLite。
8. 第一版不做 OCR、本地大模型部署、整页翻译或 macOS 支持。
9. 优先完成可自用、可演示、可比赛提交的闭环。

## 3. 技术栈

桌面框架：

```text
Tauri
```

ReadRay 当前采用 Tauri 作为桌面框架。遇到全局快捷键、窗口行为、剪贴板访问、SQLite 或 Windows 打包问题时，优先定位原因并解决，不在计划中预设替代框架。

前端：

```text
React + TypeScript
```

原生层：

```text
Rust / Tauri commands
```

数据库：

```text
SQLite
```

LLM：

```text
DeepSeek OpenAI-compatible API
```

包管理：

```text
Node：pnpm
Rust：rustup + cargo
Python 脚本：uv
```

Python 只用于辅助脚本、评测、数据处理或后续实验。桌面 App 运行时不应依赖 Python。

## 4. 轻量 Agent 设计

ReadRay 不直接嵌入 LangChain、LangGraph、pi coding-agent、Agno 或 Pydantic AI，也不为桌面应用增加 Node/Python Agent sidecar。阶段八点五参考 pi Agent Core 的循环、事件、工具和上下文协议，在现有 Rust/Tauri/SQLite 边界内实现原生 Runtime：

```text
AgentRunCoordinator
├─ ContextAssembler     投影会话、能力、工具事实与长上下文
├─ ModelGateway         统一 DeepSeek 文本、tool call、usage 与错误事件
├─ ToolRegistry         注册并按当前能力激活有类型工具
├─ ToolPolicy           校验权限、参数、预算和网络安全
├─ AgentEventSink       向前端发布文本、工具、来源和终止事件
└─ RunRepository        复用 SQLite 保存 run/step/source/compaction
```

模型在已经授权的能力集合内自主决定是否使用低风险只读工具；运行时负责最终校验、取消、预算、来源、幂等性和失败恢复。第一版不开放 Bash、任意文件读写、动态代码扩展或通用系统权限。有副作用能力只能作为 ReadRay 领域命令逐项设计。

阶段八点五建设共享 Runtime、自动外部只读检索和上下文能力。主应用完整对话与 Quick AI overlay 是首要迁移面；Runtime 稳定后，作文中的 Writing Coach 通过独立 surface adapter 接入并继续保留 `writing.rs`、文章 revision、完成版本和请求身份权威。ExplanationCard 与 Review 的确定性结构化生成不因共享 Runtime 自动迁移。长期学习者记忆、熟练状态和个性化工具仍属于阶段九。详细方案见 `docs/AGENT_RUNTIME_UPGRADE_PLAN.md`。

## 5. 数据来源与版权策略

ReadRay 不内置商业单词书，也不内置有版权风险的词典数据库。

MVP 的数据来源：

1. 用户主动选中或复制的文本。
2. 模型生成的解释。
3. 用户本地查询历史。
4. 用户后续编辑和反馈。

禁止事项：

1. 不爬取商业词典网站。
2. 不复制牛津、朗文、有道、欧路等商业词典释义。
3. 不把模型生成内容伪装成权威词典来源。

文档说明口径：

> ReadRay 不内置有版权风险的词典内容。它只在本地保存用户主动触发的学习记录和模型生成解释。

## 7. 开发阶段

### 阶段一：Tauri 基础能力打通（已完成）

目标：

打通 ReadRay 在 Windows 上所需的 Tauri 基础能力。

验收标准：

- 全局快捷键可以显示和隐藏应用窗口。
- 窗口可以置顶，并能按需隐藏。
- 可以读取剪贴板文本。
- SQLite 可以写入和读取。
- 可以在应用流程中调用 DeepSeek API。
- Windows 本地开发构建可以运行。

### 阶段二：解释卡 MVP（已完成）

目标：

完成最小可用的查询闭环。

验收标准：

- 用户可以通过手动输入或 Windows UI Automation 跨应用选区呼出 ReadRay。
- 文本可以发送给 DeepSeek。
- 应用返回结构化解释卡。
- 解释卡按 word / phrase / sentence / paragraph 分型，并按类型展示有价值的释义、语境、原句、翻译、搭配或学习提示。
- 选区查询支持最长 4096 字符，句子和段落以完整翻译为第一信息。
- LLM 输出在展示前经过 schema 校验，未定义的学习难度不强制生成或展示。

### 阶段三：本地记忆（已完成）

目标：

把每次查询变成可检索的学习记录。

验收标准：

- SQLite 保存查询文本。
- SQLite 保存解释卡内容。
- 记录包含时间、类型和可用的来源上下文；没有可靠难度时保持为空。
- 历史页面支持搜索。
- 历史页面可以按单词、短语、句子、段落过滤。
- “今天”页与“记忆”页通过 Tauri/SQLite 展示真实学习记录。

已完成 SQLite schema、迁移、解释成功后自动保存、读取/搜索/筛选/删除接口及测试，并将已验收的“今天”和“记忆”页面接到真实数据。正式页面不聚合或伪造重复出现次数；删除 command 已保留，但尚未增加未经设计验收的删除入口。

### 阶段四：完整对话正式接线（已完成）

目标：

让已经验收的完整对话页使用真实 DeepSeek 与 SQLite 会话数据。

验收标准：

- Tauri 主窗口通过可替换的 repository/service 接入真实会话，浏览器预览继续使用 fixture。
- “今天”页输入、“新对话”和最近对话可以创建、加载并继续真实会话。
- 多轮消息、失败重试和应用重启后的恢复行为一致，不丢失已保存内容。
- 复用现有 `deepseek_client`、Quick AI commands 与 SQLite schema，不在 React 组件中直接 `invoke`，也不建立第二套模型客户端。
- 当前后端不支持的流式、记忆引用等能力必须诚实降级，不用演示数据伪装真实结果。

阶段四已经完成并通过真实 Tauri 功能验收：主应用使用真实 DeepSeek/SQLite 会话，创建、加载、续聊、失败恢复、幂等重试和重启恢复均已闭环。非流式、Markdown 展示和对话策略稳定性作为已知体验债务留待后续优化，不阻塞当前路线进入阶段五。

### 阶段五：写作功能正式接线（已完成）

目标：

将已经验收的写作页面从浏览器 fixture/localStorage 骨架升级为正式桌面功能。

验收标准：

- 使用 SQLite 保存文章、草稿、版本与必要的分析结果，应用重启后可恢复。
- 新建、列表、搜索、编辑、自动保存、删除和版本回看均使用真实 repository/service。
- 通过有类型的原生命令调用 DeepSeek 完成写作分析、选区问答和再次检查；模型输出必须经过结构校验后再进入 UI。
- 问题操作、差异对比和完成稿基于真实文章与版本，不依赖硬编码 fixture。
- 保存或分析失败时保留用户正文与当前版本，不允许静默覆盖或丢失内容。
- Tauri 正式路径不再依赖 localStorage 和演示响应；浏览器预览可以保留独立 fixture。

阶段五已经完成并通过真实 Tauri 功能验收：写作文章、草稿、分析、问答、完成版本与对比基线均使用真实 SQLite/DeepSeek 数据；新建、搜索、自动保存、重启恢复、删除、连续辅导、再次检查、差异对比、版本回看、继续修改和失败重试已经闭环。“本次写作要点”随文章版本保存，但尚未进入全局复习或去重系统；该边界留待阶段八统一讨论，不阻塞当前路线进入阶段六。

### 阶段六：会话管理闭环（已完成）

目标：

补齐完整对话页之外的历史管理能力。

验收标准：

- “查看全部对话”展示真实历史，并支持稳定的加载与空/错状态。
- 支持会话重命名和删除，操作后侧栏最近对话与当前页面同步更新。
- 导出在 Tauri 中生成用户实际可取得的本地文件，并包含完整 user/assistant 消息。
- 删除、重命名和导出失败时不误报成功，也不破坏当前会话。

阶段六已经完成并通过真实 Tauri 功能验收：“查看全部对话”读取完整 SQLite 历史，侧栏最近会话与全部历史支持一致的左键打开和右键管理；当前会话标题可原地重命名，删除保留确认，原生 Markdown 导出覆盖取消、失败与成功路径。管理操作使用数据库会话 ID 和异步身份守卫，迟到结果不会回写已切换页面；侧栏、历史页与当前会话能够在操作后同步更新。

### 阶段七：设置与桌面生命周期（已完成）

目标：

提供真实可用的配置入口，并补齐 Windows 桌面应用的进入、驻留和退出路径。

验收标准：

- 设置页只展示已经接线的选项，不放置无效开关或占位功能。
- 提供 DeepSeek 密钥的首次配置、校验、更新和清除流程；敏感信息不得明文写入仓库或普通日志。
- 支持管理快捷键、开机启动和必要的本地数据选项，并持久化有效配置。
- 明确定义关闭、隐藏、托盘退出、单实例和重新打开主窗口的行为。
- overlay、主窗口和后台状态在设置变更及应用重启后保持一致。

阶段七已经完成并通过真实 Tauri 人工验收：设置页三批功能与桌面生命周期正式接线均已收口，托盘、关闭与安全退出、开机启动、单实例和两组全局快捷键的正常及故障路径符合预期。快捷键冲突降级与逐项恢复、保存失败回滚、退出期间修改隔离和取消退出状态一致性已通过复审。

2026-08-25 的单手操作补强不改变阶段七状态：新安装默认以双击左 Alt 触发选区解释、以 Alt+Win+Space 触发快速查询；已有用户保留原快捷键。普通组合键继续走 Tauri 全局注册，高级修饰键手势由 Windows 原生层处理；版本化 binding、迁移、录制和自动验证已实现，真实输入法、应用菜单、管理员窗口与安全桌面边界仍按 `docs/HANDOFF.md` 的矩阵单独人工验收。

### 阶段八：复习闭环（已完成）

目标：

在真实学习数据和对话/写作链路稳定后，认真定义复习模型并形成最小闭环。

进入本阶段前先完成产品讨论：

- 复习对象是什么。
- 优先级由哪些真实信号决定。
- “记得”“忘了”如何影响下一次出现。
- 哪些行为属于复习，哪些只是历史浏览。

验收标准：

- 自动生成可持续浏览的当日复习 Feed，且每个条目都能追溯到真实学习记录；同一目标完成一轮后允许以新的英文语境再次出现。
- 优先级算法有明确、可解释的输入，不凭空生成高频词、趋势或薄弱项。
- 支持“记得”和“忘了”反馈，并更新条目状态与下次复习时间。
- 复习结果写回本地数据，失败可重试且成功结果可撤销；卡片质量反馈与学习结果分开保存。

阶段八已经完成独立 code review、自动验证和真实 Tauri/SQLite/DeepSeek 与视觉交互人工验收。本阶段实现 learning record 一记录一目标、可持续分页的当日 Feed、主应用启动及学习记录更新后的首屏后台预热、学习事件中完整英文语境直用、缺失语境时按需后台生成、30 天有效且以 3/256 为软容量并保护 Feed 引用的持久化卡片、第四轮起三卡轮换、SQLite v14 安全清理、v15 target 一致性审计与 v16 中间版质量反馈表兼容迁移、持久化制卡失败退避、pending/失败条目不丢失、整轮完成后才创建同目标下一语境、内容自适应 editorial 卡片与 3D 翻转、提示/揭晓、remembered/forgotten、调度、任意生效 attempt 撤销、SQLite 权威对账、真实来源，以及与学习结果分离、按具体卡片语境隔离的即时质量反馈；同一卡片未发送意图采用最后选择，不同卡片全部串行保存，已发送请求冻结完整幂等输入并在直接成功或权威确认的模糊成功后统一收口。应用安全退出等待全部质量反馈预读、写回和对账，未解决失败会阻止退出。写作、Quick AI、长期学习者记忆、主动表达和 Markdown 复盘不属于阶段八；基于长期记忆的推荐式优先级属于阶段九。

### 阶段八点五：Agent Runtime 升级（任务 1/2/3/4/5/6 全部完成）

目标：

建立供主应用完整对话、Quick AI overlay 和 Writing Coach 复用的 Agent Runtime，把现有一次流式模型请求升级为具备自主工具选择、循环执行、来源、取消、恢复和安全策略的现代 Agent，同时保持各业务现有 SQLite、revision、幂等重试、凭据与迟到结果边界。

验收标准：

- 支持多轮“模型 -> 工具 -> 模型”循环，并有明确预算和终止条件。
- 模型自主判断是否使用已授权的低风险只读工具，无需用户逐次选择是否联网。
- 实时公共信息能够自动检索、展示结构化来源，失败时不冒充已核实结论。
- 工具调用有 schema、active allowlist、权限分级、超时、取消和确定性结果顺序。
- 重试、重启和 IPC 丢失不会重复 user、assistant、tool result 或副作用。
- 不开放 Bash、任意文件读写、动态扩展或其他通用高风险权限。
- 长上下文可追溯压缩与阶段九学习者记忆严格分离。
- 主应用对话与 Quick AI overlay 共享同一对话适配器；Writing Coach 通过独立适配器复用同一内核，且不绕过 `writing.rs` 或直接覆盖草稿。

完整任务拆分、架构、安全与验收门禁见 `docs/AGENT_RUNTIME_UPGRADE_PLAN.md`。任务 0/1/2/3/4/5/6 已于 2026-08-16/17/18 全部完成并通过评审（任务 3/4/5/6 已正式收口，任务 3/4 含真实 Tauri 使用验收），**阶段八点五 Agent Runtime 升级全部完成**；任务 4 的"编辑并重新生成"已按 §18.4 覆盖式语义正式开放，任务 5 已落地预算驱动长上下文投影 + 方案 A 最简折叠兜底，任务 6 Writing Coach 已接入共享 Runtime（写作权威保留、流式状态/取消、检查方式 B(1) 修正）。已知问题"写作检查曾返回 0 个问题"已记录待后续处理（见升级方案任务 6 实施记录）。

验收标准：

## 9. 主要风险

风险：Tauri 桌面能力接入过程中遇到问题。

应对：优先定位具体原因，查官方文档、最小复现和本地环境配置，不把切换框架作为默认计划。

风险：项目被认为只是简单查词软件。

应对：强调本地记忆、复盘规划、用户画像和可量化的操作流程缩短。

风险：LLM 输出不稳定。

应对：使用结构化 JSON 输出和 schema 校验。

风险：单人开发范围失控。

应对：MVP 闭环跑通前，不做 OCR、本地模型部署、插件生态或跨平台支持。

风险：词典版权问题。

应对：不内置商业词典内容，只使用用户主动触发的文本和模型生成解释。

风险：演示实现进入正式路径。

应对：浏览器预览和 Tauri 正式装配明确分离；正式页面只依赖有类型的 service/repository，无真实结果时展示空态或错误态。

风险：模型输出或保存失败导致内容丢失。

应对：写作和对话先保存用户输入，再执行模型调用；模型返回经过结构校验后才进入正式状态，保存、重试和版本切换必须保留可恢复状态。

风险：设置与桌面行为只有界面没有闭环。

应对：设置页只暴露已经实现并可验证的配置，并将密钥、快捷键、托盘、单实例和关闭策略作为同一桌面生命周期阶段验收。

风险：Agent 自主工具调用放大模型错误或外部 prompt injection。

应对：只向模型暴露当前 active allowlist；低风险只读工具也必须经过 Rust 最终校验、运行预算、来源与网络策略，有副作用能力使用领域命令和确认机制，禁止 Bash、任意文件读写和动态代码扩展。
