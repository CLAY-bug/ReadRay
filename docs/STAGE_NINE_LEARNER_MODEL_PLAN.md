# 阶段九：学习者模型与个性化方案（讨论草案）

最后更新：2026-08-14

状态：讨论草案，阶段九尚未开始

## 1. 这份文档解决什么问题

阶段九需要单独讨论长期学习者记忆、熟练程度和个性化推荐。此前已经形成了一些方向，但还没有完整方案。这份文档先把已经讨论清楚的部分记下来，供后续新会话继续推敲。

它不是数据库设计，也不代表阶段九已经进入实现。表结构、评分公式、时间衰减、模型调用方式和迁移版本都要在产品语义确定后再决定。

阶段九的范围暂定为：

> 复习交互重构 + 跨查询、复习、写作的证据系统 + 长期熟练度模型 + 个性化推荐

## 2. 产品出发点

ReadRay 不应要求用户频繁判断“我到底会不会这个词”。这种判断模糊、费力，也容易受到当下心情和答案呈现方式影响。用户的主要任务仍是阅读、查询和写作；系统根据这些自然行为逐步修正判断。

目前确认的方向：

- 查询、复习和写作中的真实行为是学习者模型的输入。
- 阅读复习卡属于再次接触，不能直接证明已经掌握。
- 写作中的独立、正确使用比浏览卡片更能说明主动掌握。
- ReadRay 在后台调整推荐频率，不要求用户维护进度表或持续自评。
- 系统判断必须能解释、关闭、纠正和回退，不能只保存一个无法追溯的模型结论。

## 3. 当前复习页只是过渡状态

复习卡现在点击后直接展示完整语境、翻译、释义和例句，不再挖空，也不再提供提示和翻面步骤。

“想起来了 / 没想起来”仍暂时保留，因为阶段八的 Feed 完成、下一轮创建、调度和撤销都依赖 `remembered/forgotten` attempt。完整答案已经可见，因此新提交统一按 `usedHint=true` 处理，避免旧调度把它误认为无辅助回忆成功。

阶段九只有在新的证据与调度链路能够接替这些职责后，才删除两个自评按钮。不能先隐藏按钮，再让 Feed 失去持久化完成语义。

旧 attempt 可以保留为历史自评，但不能直接当成用户真实熟练度。阶段九需要决定它们是否作为低可信证据参与初始状态重建。

## 4. 行为证据的初步解释

目前只确定证据方向，不确定权重。

| 行为 | 初步解释 | 可信程度 | 主要风险 |
| --- | --- | --- | --- |
| 第一次查询某个目标 | 用户可能不熟悉，也可能只是在确认细节 | 低 | 不能直接判定“完全不会” |
| 短期内反复查询 | 尚未稳定掌握的可能性上升 | 中 | 也可能是在比较不同语境 |
| 打开复习卡 | 完成一次接触，适合影响近期冷却时间 | 低 | 看过答案不等于记住 |
| 阅读 Agent 提供的表达 | 获得一次输入 | 低 | 内容来自 Agent，不是用户输出 |
| 接受 Agent 改写 | 用户认可或使用了建议 | 低到中 | 不能冒充用户独立表达 |
| 写作中独立、正确使用 | 能主动调用目标表达 | 高 | 必须排除复制、粘贴和 Agent 代写 |
| 间隔一段时间后再次正确使用 | 主动掌握更稳定 | 高 | 仍需检查语境和用法 |
| 使用错误并被纠正 | 当前用法仍不稳定 | 中到高 | 应保留错误类型和对应语境 |

点击次数不能直接累加成熟练度。点击卡片可以降低短期重复推荐，但不应让主动输出能力明显上升。相反，多次重新查询可能是尚未掌握的信号。

## 5. 熟练程度不能只靠一个计数器

同一个词可能处于“看得懂，但写不出来”的状态。阶段九至少要区分以下信息：

- 识别熟悉度：看到目标表达时能否理解。
- 主动输出能力：写作时能否独立、正确使用。
- 判断置信度：现有证据是否足够，证据之间是否冲突。
- 时间状态：最近一次查询、接触、错误和有效输出发生在什么时候。

复习排序可以使用一个派生优先级，但底层不应只保存“熟练度 +1”。是否需要更多维度、是否向用户显示概括状态，留到后续讨论。

熟练状态还需要时间因素。一次正确使用不能永久证明掌握；隔一段时间后的再次正确使用，比连续几分钟内重复出现更有价值。

## 6. Agent 与本地规则如何分工

大模型适合判断语义，不适合直接维护不可解释的长期分数。

建议的职责边界：

- 本地事件是事实来源，记录发生了什么、何时发生、来自哪个功能和哪条学习目标。
- Agent 判断写作中的表达是否对应目标、用法是否正确、是否存在可迁移的错误。
- 本地规则根据证据类型、时间和算法版本更新派生状态。
- 推荐器读取派生状态并给出可解释的排序原因。

不能让一次模型调用直接写入“用户已掌握”并覆盖历史。模型输出需要结构化校验、置信度和来源；派生状态应能从证据重新计算。

## 7. 预期的产品行为

### 7.1 查询

- 首次查询建立或关联稳定学习目标。
- 重复查询、查询间隔和语境变化进入证据链。
- 查询次数本身不等于熟练程度，但可参与“不熟悉程度”的判断。

### 7.2 复习

- 打开卡片自动记录一次接触，不再要求用户判断“想起来了 / 没想起来”。
- 一次接触主要影响近期冷却，不能显著抬高主动输出能力。
- 推荐卡片可以说明原因，例如“近期查询 3 次”或“尚未在写作中使用”。
- 用户仍可选择“暂时不推荐”“这不是我想学的”或纠正错误记忆。这些操作属于控制和纠错，不是熟练度自评。

### 7.3 写作

- ReadRay 可以在合适的写作主题或辅导中温和地带入薄弱表达，不应机械塞词。
- 用户在看到建议前独立使用目标表达，属于强证据。
- 接受 Agent 建议、复制文本和独立输入必须区分来源。
- Agent 需要判断用法是否自然、是否对应当前学习目标，不能只做字符串匹配。
- 隔一段时间后的再次正确使用，应比同一轮写作中的重复出现更有价值。

### 7.4 解释与推荐

- 长期记忆可以影响复习排序，也可以影响解释深度、例句选择和写作提示。
- 注入模型的历史信息必须与当前目标相关，不得把无关记录拼进 prompt。
- 推荐变化需要能够说明依据，用户可以关闭个性化或清除派生状态。

## 8. 现有基础与缺口

### 已有基础

- SQLite v19 已建立稳定 `learningTargetId`、真实 occurrence 和目标级复习状态。
- 原始 `learning_records` 继续追加保存，可追溯重复查询、时间、来源和语境。
- Review 已有持久 Feed、生成卡、attempt、撤销、质量反馈和 SQLite 权威对账。
- Writing 已保存草稿 revision、分析、完成版本和问答记录。

### 仍缺少

- 跨功能统一的学习证据语义。
- 能重放、重算和回退的熟练状态。
- 写作表达的来源标记，当前快照不足以可靠区分独立输入、粘贴和 Agent 建议。
- 不依赖人工自评的 Feed 完成与调度方式。
- 推荐原因、个性化开关、纠错和清除入口。
- 用真实样本评估推荐是否有效的指标与基线。

## 9. 暂定实施顺序

以下顺序用于组织下一次讨论，不是已经批准的任务拆分。

1. 先确定证据语义：哪些行为进入模型，分别说明什么，哪些行为明确不能作为掌握证据。
2. 再确定熟练状态：维度、置信度、时间衰减、冲突证据和旧数据处理。
3. 设计追加式证据存储与可重建派生状态，集中完成一次经过审计的 migration。
4. 用新的“接触事件”接管 Review 完成与近期冷却，再删除人工自评按钮。
5. 为 Writing 增加必要的来源与修改轨迹，接入主动输出判断。
6. 接入复习排序、解释和写作强化，并提供推荐原因和用户控制。
7. 建立可复现实验，比较改动前后的查询、复习和写作表现。

这里不预设表名、字段或分数。数据库方案应在前两步完成后一次设计，避免边讨论边增加 migration。

## 10. 数据与实现约束

- 不修改或删除追加式原始学习事件。
- 新证据必须带稳定目标身份、来源、时间和幂等身份。
- Agent 生成的内容不能冒充用户主动输出。
- 派生状态要带算法版本，并能从事实事件重新计算。
- 旧 `remembered/forgotten`、卡片质量反馈和查询次数都不能单独冒充学习者画像。
- 后台任务必须遵守现有 request identity、revision、取消和迟到结果隔离规则。
- 个性化关闭后应回到可解释的非个性化排序，不破坏原始数据。
- 清除或回退只处理派生记忆，不应删除用户的真实查询和写作历史。

## 11. 验收方向草案

阶段九完成时，至少应能回答以下问题：

- 为什么这个目标今天被推荐？
- 系统依据的是查询、复习接触、主动输出还是错误记录？
- Agent 建议是否被错误算成用户能力？
- 同一事件重复提交、应用重启或模型迟到时，状态是否仍一致？
- 用户关闭个性化、纠正判断或清除派生记忆后，系统能否可靠回退？
- 推荐是否让重复查询减少、间隔后的正确使用增加，而不只是让页面看起来更智能？

具体验收指标和阈值仍需在正式方案中确定。

## 12. 下一次讨论要解决的问题

建议新会话按以下顺序推进：

1. 定义目标：阶段九第一版究竟优化什么，不同时追求所有个性化能力。
2. 审查证据表：补充、删除或调整上述行为解释。
3. 确定熟练状态需要几个维度，以及时间衰减如何表达。
4. 决定如何识别写作中的独立输出和 Agent 建议来源。
5. 决定 Agent 何时介入、输出什么结构、如何缓存和验证。
6. 讨论旧 attempt 的兼容方式，以及新的 Review 完成语义。
7. 确定用户控制、解释界面和效果评估。
8. 产品语义稳定后再设计 migration、任务拆分和验收清单。

开始新会话时，先阅读 `AGENTS.md`、`docs/RESOURCE_MAP.yml`、`docs/DEVELOPMENT_PLAN.md`、`docs/HANDOFF.md` 和本文。阶段九在用户明确批准实现前继续保持暂停。
